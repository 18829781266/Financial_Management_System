# 汇通云 · 电子会计档案（在线本地数据版）

Vue3 / TypeScript / Element Plus / PageFlip。七个操作模块：工作台、数据采集、智能匹配、异常处理、电子档案、规则配置、操作日志。

## 运行与测试

```sh
npm ci
npm run dev
npm test
npm run build
```

浏览器回归步骤见 `tests/README.md`。发布静态文件在 `dist/`；`.openai/hosting.json` 保留既有私有站点ID。

## 批量导入

- 支持直接选择 ZIP，或同时选择 JSON / CSV / PDF / PNG / JPG。单次最多100个源文件，结构化凭证最多5000行；压缩包兼容UTF-8/GBK中文名。
- JSON/CSV自动校验格式与字段，整个待导入批次先校验再提交，重复或错误记录不会半批写入。
- 文字型凭证PDF按坐标读取金额及原借贷分录，自动合并同号续页；文字型发票读取价税合计、日期和购销主体，支持的银行回单按抬头分拆同页多单。ZIP可混合导入两类记录，整批预校验和文件保存。无文字层的扫描PDF/图片仍需补录或接入OCR。
- 提取记录导入后统一显示“待匹配”。只有点击智能匹配页的“开始自动匹配”才执行规则：已关联显示“已匹配归档”，未关联显示“请复核”；人工复核保存不代表已经关联，正式PDF归档仍要求完整校验。零净额、红字和多客商凭证保留原金额与分录，进入专项处理，不用正数金额伪造通过。原件没有注明的附件数保持未知。
- 文件存入IndexedDB，结构化信息存入localStorage，刷新后仍可查看和下载原件。数据仅在当前浏览器，不会跨设备同步。

## 批量删除与关联

记账凭证和原始单据列表支持勾选本页、多选、确认批量删除。已归档的凭证及其关联单据不可删除。删除未归档已匹配凭证会释放单据；删除匹配组中的单据会解除该组，凭证重新进入待匹配。全部关键操作写入日志。

支持编辑待匹配凭证、补录单据、恢复附件缺失、手工关联、解除未归档匹配，以及匹配后的发票印章人工补核。

## 电子档案

- 匹配成功的凭证与单据同步到“已匹配归档”，展示已核对的凭证附件关系或有明确依据的企业名称关联。付款 / 收款名称与凭证单位一致时，同一企业原件可归入名称关联组；无对应关系的单据继续留在复核池。不同类型单据独立汇总，正式PDF档案册的校验锁定分别管理。
- 默认工作空间为空，不自动生成演示凭证或历史样册。已有数据保留，点击重置可清空全部记录及原件。
- 新生成的档案合并已上传的实际PDF/图片，顺序为凭证及关联单据。没有上传影像的记录生成标明来源的结构化信息页，不虚构原始票据、印章或查验结果。
- 上传原件支持直接翻页预览，保留PDF/图片原始版式。归档PDF和SHA-256保存后重复下载直接读取同一文件，并验证哈希；正式会计存证仍需配套后端、原件复核和企业档案制度。
- 归档生成失败会撤销本次元数据及其锁定，不留下半成品。

## 验收边界

这是浏览器本地数据模式，尚未接通真实ERP/OCR/MySQL/Redis。哈希和前端只读标记不是法定防篡改认证。真实准确率和后台并发必须在实际环境及独立标注集上另行验收。

## V1.2 金额校验修复

空金额显示“未录入”，不再作为0元计入合计。确认导入时按文件/行/字段列出全部缺失项，支持跨页定位；有错误时整批不写入。人民币符号、规范千分位、全角数字共用一个严格解析器。V1.2 时PDF影像仍需人工补录；V1.3 新增文字层提取，扫描OCR仍未接入。

## V1.4 阅读与导入顺序

凭证、单据、异常池及检索列表按实际导入顺序倒序，成功提交时保存导入时间与递增序号，同批后行优先；与业务日期无关，刷新后顺序保留。旧凭证按追加方向兼容，旧单据按头插方向兼容。编辑和复核不改变导入先后。

全站正文及表格约13–14px，凭证号加粗蓝色，金额15px加粗等宽数字，客商和状态提高对比度。翻页区域按纸张比例铺满宽度，窄屏自动单页，全屏变化重新计算折页坐标；目录与凭证底部信息不再与页脚重叠。手机取消固定操作列，横向滑动查看更多字段。

新增16项排序测试，全套165项单元测试通过；旧86项浏览器回归、新增10项导入顺序检查、45项视觉与交互检查通过。

## V1.5 付款人归集与匹配同步

原始单据的客商名称取付款人：发票取购买方，银行回单按明确的付款/收款角色提取，收款人单列。原件没有列付款人的记录留空并提示“请复核”，不拿收款人替代。旧文字PDF在原件仍保存在当前浏览器时自动重读迁移，保留旧客商值供核对；非锁定自动关联重新校验，人工和已锁定关系保留。

规则引擎按已保存的优先级、启用状态、匹配策略、名称字段、单据类型、日期窗口、金额容差和置信度执行。精确、模糊与同类单据汇总分开处理；多解或候选被多张凭证争用时保留人工处理，避免重复消费。进入智能匹配会处理新增采集数据、补录变更和已修改配置，列表同时显示真实关联状态和独立复核提示。

匹配结果与付款人归集工作稿持久化保存；编辑、解除、删除同步更新工作稿引用。新增工作稿列表也按导入顺序优先显示最新数据，正式归档继续检查复核、印章、附件数和金额。

验证使用隔离浏览器，实际财务文件和浏览器存储不会进入源码或部署包。详见 `tests/付款人匹配验证.md`。

## V1.6 原始单据翻阅

匹配工作稿和新生成档案的翻页预览直接读取当前浏览器中保存的原始PDF、PNG、JPG；银行回单的字段位置、横竖方向、颜色、印章和原有留白均按原件显示，不再根据提取字段重新绘制票据。多页PDF逐页展开，目录、跳页和总页数同步更新；只有一页时完整静态展示。

原件只做等比预览，不裁切或改写字节。邻近页按需渲染，切换档案会取消旧加载并释放画布、PDF和图片临时地址。缺失或损坏原件明确提示；已有内置样册仍标为演示，与用户原件区分。正式PDF合并及SHA-256流程保持独立。

247项单元测试、22项原件预览浏览器检查、20项原有归档回归通过，覆盖横版/竖版/旋转页、PNG、单页、目录、多页跳转、缩放全屏、手机与资源释放。用户压缩包另在隔离浏览器完成25项检查，含23份银行单据连续原样翻阅、刷新和实际原件页码；原件和截图不进入源码或发布文件。

## V1.7 手动触发与三态流转

刚导入的凭证和单据统一待匹配。进入页面、修改规则、补录或保存人工复核均不运行匹配，必须点击智能匹配页的开始自动匹配按钮。成功关联显示已匹配归档；本次期间内未关联凭证及孤儿单据显示请复核，新导入批次或未执行期间保持待匹配。人工复核保存后仍需关联，单独复核不会进入电子档案。

电子档案的已匹配归档页只由实际matched凭证和matched单据的双边引用构造。未关联记录不参与分组、金额、目录或原件翻阅，也不在档案页显示未命中清单；档案凭证检索同样只显示已关联数据。解绑或删除会立即移除档案展示并转入复核。旧存储恢复时清理曾按同名全归集的未关联引用，并根据运行结果及导入游标恢复状态。

此前V1.5的进入页面自动执行、同付款人全单据工作稿展示由本版本替代。原始PDF/图片翻页与正式档案合并、印章校验和SHA-256流程保留。

V1.7最终验证：255项单元、162项浏览器检查和18项实际压缩包流程检查通过，浏览器异常为0。浏览器检查包含全模块46、金额20、新状态34、规则20、归档20及原件22项；验证产物不进入部署包。

## V1.8 付款 / 收款企业名称关联修复

此前默认仅将单据付款人与凭证往来客商按金额日期比较，遗漏了收款人和凭证单位名称，用户提供的同一企业原件因此无法关联。新增默认启用的R08：按会计期间比较付款人或收款人与凭证单位名称；未提取单位时按往来客商比较，默认名称归一后100%一致。名称字段、单据类型、阈值和启用状态可配置。同时命中多个核算单位时保留复核。

企业名称关联独立保存依据和成员，归档页标明“企业名称关联”，可翻阅全部原始凭证及单据。原R01—R07金额附件核对保留，单据仍只能被一组财务关系消费；名称关联不改写原金额、分录、印章或逐凭证附件关系，也不放行正式PDF校验。关联穿透可查看名称依据并跳转企业原件；可解除、删除或修改主体，新增同名数据在再次点击按钮前仍待匹配。

旧存储自动补充R08，已有数据无需重新导入；规则变更和页面导航不运行匹配。验证包含276项全套单元及新增旧版本迁移回归，名称模块22项独立测试、184项浏览器检查及22项实际压缩包检查。实际验证同一企业27张凭证、36份单据（付款侧23份、收款侧13份）通过名称关联，64页原件可翻阅；正式凭证金额关系保持独立。财务文件、浏览器存储和截图不进入源码或静态部署包。

## V1.9 原始单据关联状态与档案同步

修复仅导入银行回单、没有同期间凭证时无法归档展示的问题。R08在凭证主体关联之外，支持同期间至少两份原始单据按配置的付款人、收款人或任一侧名称建立独立名称组；多个主体的支持度相同且成员不同则保留复核，不沿交易对手传递合并。单据之间的名称关联不创建虚构凭证或金额附件关系。

采集状态、原件档案成员与运行数量统一从已保存的有效关联计算。结果区分别展示已关联、新增和请复核的单据数量；再次运行切换到对应期间及最新原件组。档案支持没有凭证的名称组，直接翻阅已关联原始PDF；未命中原件仍请复核，不进入该组。新导入单据在下一次点击匹配前仍待匹配。

验证：285项单元测试；新增22项“5份关联、2份复核、无同期间凭证”的浏览器检查，另有名称22项、原状态闭环34项、全模块46项回归全部通过。实际压缩包36份原始单据在不导入同期间凭证时可名称关联并展示36页原件，刷新保持，浏览器异常为0。原始数据及验证产物仅保留在私有工作目录，不进入源码与部署包。

## V3.0 登录与账号权限

新增蓝色云档案登录页。会话验证通过后才挂载业务工作区，姓名、头像和角色取自服务端；提供退出登录、刷新恢复、定时核验和跨标签会话同步。账号及权限保存于托管 D1，现有凭证、原件和匹配记录继续保存在当前浏览器，不迁移或清空。Sites 的站点访问范围与应用账号权限独立，发布时保留既有范围。

超级管理员固定账号 `admin`、姓名赵会计，通过运行时 secret `ADMIN_PASSWORD_HASH` 首次幂等初始化；不在源码、页面或浏览器存储中保存管理员明文密码。用户管理仅超级管理员可见，可创建普通用户，账号不可重复；普通用户可登录并使用业务模块，不能列出或创建账号。服务端每次读取真实角色，拒绝前端伪造角色和跨站写请求，不依赖隐藏按钮授权。

密码使用独立随机盐的 PBKDF2-SHA256（100000 次）；会话使用32字节随机令牌，仅在数据库保存 SHA-256 摘要，通过 Secure、HttpOnly、SameSite=Strict Cookie 发送，12小时到期；退出删除服务端会话。账号及 IP 登录失败次数持久化限流，日志及错误响应不返回密码或令牌。

部署形态由静态资产扩展为 Worker + Vue assets + D1；`npm run build` 生成完整产物，并将迁移复制至 Sites 官方要求的 `dist/.openai/drizzle`，`npm run db:generate` 生成 schema-only 迁移。`npm run db:local` 只迁移本地数据库，`npm run preview` 使用隔离本地配置。开发初始化摘要放在忽略的 `.sites-runtime/.dev.vars`；该文件不复制到发布包，生产摘要须通过 Sites secret 设置。原“清空所有数据”只清业务数据及原件，不删除服务端账号。
