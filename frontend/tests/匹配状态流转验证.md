# V1.7 采集状态与档案边界

本版本按最新要求替代V1.5的进入页面自动匹配、同付款人全单据工作稿展示。所有测试使用隔离浏览器；实际业务文件、存储和截图不进入源码或发布静态文件。

## 状态与动作

| 操作 | 采集列表状态 | 电子档案展示 |
| --- | --- | --- |
| 刚导入 | 待匹配 | 不展示新记录 |
| 进入智能匹配、修改规则 | 不变 | 不变 |
| 点击开始自动匹配，规则关联成功 | 已匹配归档 | 展示真实关联凭证和单据 |
| 点击开始自动匹配，未关联或孤儿单据 | 请复核 | 不展示 |
| 人工复核保存，尚未关联 | 仍为请复核 | 不展示 |
| 人工复核并手工绑定成功 | 已匹配归档 | 展示真实关联 |
| 解绑、删除关联记录 | 释放的记录请复核 | 移除关联展示 |

“已匹配归档”是列表与关联展示状态。正式PDF档案册仍保留原件、字段、印章、金额和附件数校验、合并、SHA-256与只读保护；不因改状态标签而跳过校验。

## 实现与验证

内部关系状态和字段复核标记保留，新增匹配失败复核标记。新导入不继承外部状态，运行只影响选定期间；复核保存不等于绑定。旧存储依据运行结果、原因和导入序号恢复，跨期间旧复核不丢失，后导入的新批次不继承旧运行结果。

档案分组、金额、原件目录和预览仅取matched凭证指向matched单据的有效双边引用；同付款人的未关联单据不混入，未关联原因列表移至复核池。档案页的凭证检索同样只显示已关联凭证。

全套255项单元测试通过，新增8项流程回归。可复现浏览器脚本：`match_status_workflow.py`、`matching_workflow.py`、`archive_workflow.py`、`original_preview.py`。它们检查按钮触发、三态、人工关联闭环、期间隔离、刷新、规则实际执行、原件翻阅、PDF哈希及锁定。

实际压缩包完整导入27张凭证和36份单据。默认规则运行后未命中记录进入请复核且不在档案展示；把配置窗口调为30天并选择银行回单汇总后，必须再次点击按钮才运行。真实命中2张凭证及6份单据，其余25张凭证和30份单据保留请复核；同付款人的第7份未关联回单不计入该组金额及预览。刷新后状态与引用保留，浏览器异常为0。

最终固定生产构建的162项浏览器检查通过：全模块46、金额20、新状态34、规则20、原归档20、原件预览22。实际压缩包18项流程检查通过；各套浏览器异常均为0。
